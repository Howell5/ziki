## 下一步与证据格式

### P2 账号子阶段（2026-09-13）

- 实现：条件启用 Google/Discord、Cloudflare 邮件 OTP、双语账号页、显式设备码核对/批准/拒绝。缺少配置时不显示可用登录；开启身份也不开放语音/支付。BYOK、原生录音、现有官网均未改动。
- 安全：OTP 哈希、5 分钟/3 次尝试、原子邮箱冷却；同源请求、HttpOnly cookie、认证路由白名单、已验证邮箱才能批准设备、nonce CSP/noindex；不暴露浏览器 bearer 或任意模型代理。
- 测试发现并修复：Better Auth 会吞掉邮件 callback 异常并返回成功，现按请求跟踪失败、由 after hook 返回 503；限流发生在生成 OTP 前，拒绝重发不会覆盖已收到的代码。
- 自动化：账本 16 项、既有认证 7 项、新登录 10 项、账号模板 6 项，共 **39 项**覆盖；内联 JS 独立 Node 语法 **4 项**。按受影响文件复用通过记录，不反复全跑。最初测试 fixture 共用 IPv6 /64 被正确限流，已分离测试 IP；D1 LIKE 长度限制改为精确 identifier 查询，不修改生产限制。
- 本地数据库：第 3 个迁移应用成功，再次执行无待迁移项；类型检查和 Workers dry-run 构建通过。没有新的依赖版本，沿用 P1 audit 证据。
- 浏览器：Ego TaskSpace 19，本地 workerd 邮件模拟器 + D1，`example.invalid` 测试身份。走通验证码→Cookie 登录→设备码核对批准→领取令牌→重复领取拒绝→令牌退出；另验证浏览器退出后第二次登录、余额刷新、中文 390px 无横向溢出、未登录时优先展示登录表单、无效设备码不能批准。没有真实邮件发送或原生 App 登录冒烟。
- 分工：低阶 `gpt-5.6-luna` 子代理实现账号页；主代理负责认证/限流、测试、错误处理、复核状态竞态与浏览器验收。frontend-design 指导双语窄屏、可访问性与现有纸白/墨色视觉延续。
- 真实阶段门槛：Google/Discord OAuth 配置、Cloudflare 发信域名/发送能力、独立百炼新加坡账户 Key/Workspace 与授权测试预算。仍无 Stripe 测试凭证/商品、正式价格或应用许可；P2 未退出，P3/P4 未完成。不以本地 fixture 代替外部验收，不部署收费服务或发布未完成的客户端。
