## 本地 Google 登录阻塞修复（2026-11-10）

- 基于 `ade84e0`，新增 `npm run dev:proxy`，保留原 `dev` 命令、现有本地 D1 与忽略的凭证配置；仅影响本地开发启动，不修改 Google 控制台或生产配置。
- 根因证据：Google 已接受完整回调并导航至本地 `/api/auth/callback/google`，但 workerd 直连令牌接口超时。通过现有 HTTP 代理的相同无凭证探测约 0.9 秒收到响应。Better Auth 在换取令牌前消费 state，刷新回调后的 `state_mismatch` 掩盖了首次出站超时。
- 真实验收：ego lite 中用户指定的 Google 账号完成授权，返回 `/account` 显示已登录及可用额度。未关闭 state 校验，未导出浏览器会话或记录令牌。
- 回归：TypeScript、18 项认证/登录用例通过；本地代理专项覆盖 workerd POST、手动重定向、脱敏 502 与 WebSocket 回声。WebSocket 仍使用直连，尚未证明真实语音链路；P2 未退出，不发布未完成客户端。

## 百炼认证根因定位（2026-11-11）

- 基于 `3e3d963` 的工作区，读取忽略的 `.env`；无 shell 或其他 dotenv 文件覆盖，Key 无多余引号/空格。全程只输出状态码和错误类别。
- 同一 Key 对新加坡专属/公共域名的 `/compatible-mode/v1/models` 均返回 `401 invalid_api_key`；对北京公共域名及配置中 Workspace 的北京专属域名均返回 `200` 和 182 个模型。北京公共接口的无 Key、无效 Key 对照均返回 `401`，排除公开目录造成的假成功。
- 结论：当前 Key 与 Workspace 是可用于北京的有效组合，和固定新加坡的服务端路由不匹配；不能据此称 Key 已失效。检查只读取模型目录，未生成内容或发送音频，未修改凭证、区域或账单配置。

## 北京区域真实链路验收（2026-11-12）

- 基于 `98b4e3c` 的 P2 工作区，按用户要求将托管 FunASR 与 Qwen3.5 Flash 的工作空间域名固定为北京；同步配置示例、Cloud 隐私说明和诊断区域，保留 BYOK 的区域选择及个人凭证隔离。
