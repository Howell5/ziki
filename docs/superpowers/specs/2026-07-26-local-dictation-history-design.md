# Sotto 本地听写历史设计

## 目标

为系统粘贴路线补齐可靠性闭环。Sotto 无法可靠知道目标应用是否接受了 `⌘V`，因此每次得到非空的最终听写文本后，必须先保存到本地历史，再尝试系统粘贴。

历史用于找回和复制文字，不是录音管理器，也不负责再次主动粘贴。

## 已确认的产品边界

- 每次有效听写都保存，不按“粘贴成功／失败”区分。
- 只保存整理后实际用于粘贴的最终文本。
- 保存完成时间和当时使用的语音服务。
- 不保存录音、实时识别片段、整理前原文、目标 App、窗口、PID 或复制状态。
- 默认固定保留 30 天，到期自动删除；首版不提供永久保留设置。
- 每条记录支持复制和删除。
- 复制只把文字放入剪贴板，由用户决定粘贴到哪里；不提供“重新粘贴”。
- 支持搜索和“清空全部”；清空全部必须二次确认。
- 所有数据只保存在本机。

## 方案比较

### 方案 A：原子 JSON 文件（采用）

在 Application Support 中保存一个带版本号的 JSON 文件。Sotto 是单进程应用，写入由主 actor 串行执行；30 天数据量有限，全文搜索可直接在内存完成。

优点是无额外依赖、结构透明、迁移简单。缺点是不适合数万条记录或复杂查询，但不属于当前范围。

### 方案 B：SQLite

适合大量历史、分页、复杂索引和统计。当前只有 30 天、简单搜索和删除，引入数据库 schema、迁移和查询层会扩大实现与维护成本。

### 方案 C：Core Data

与 SwiftUI 集成成熟，但对象模型、迁移和持久化栈对这个小功能过重；同时 Sotto 仍支持 macOS 13，不能使用更轻的 SwiftData。

## 数据模型与存储

文件位置：

`~/Library/Application Support/Sotto/dictation-history.json`

文件结构包含：

- `schemaVersion`: 当前为 `1`
- `entries`: 历史记录数组

每条记录包含：

- `id`: UUID
- `text`: 非空的最终文本
- `createdAt`: 完成时间
- `providerID`: 语音服务的稳定标识

`providerID` 使用听写开始时捕获的 `SpeechProviderKind.rawValue`，避免用户在处理期间修改设置导致记录错配。历史页面遇到未知标识时显示“未知语音服务”，但仍保留原始标识以兼容未来版本。

写入使用原子替换。首次加载、每次新增以及打开历史页面时清理 `createdAt <= 当前时间 - 30 天` 的记录，并在有变化时落盘。

store 还要根据最早一条记录的到期时间安排单个清理任务；任务到期后清理、持久化并为下一条到期记录重新调度。新增或删除记录后重新计算任务，从而保证 App 长期运行时也遵守 30 天承诺。到期清理持久化失败时保留错误状态，并在 5 分钟后重试。

如果文件无法解码，保留原文件并改名为带时间戳的损坏备份，然后从空历史开始。保存失败不得阻断本次系统粘贴，但历史页面要显示非阻塞错误，诊断日志不得包含完整听写文本。

新增记录保存失败时保留本次内存记录、显示错误，并在下一次文件操作时再次尝试保存；系统粘贴继续执行。单条删除或清空全部保存失败时回滚内存变化，避免 UI 表示已删除但重启后记录重新出现。

## 数据流

1. ASR 返回非空文本。
2. 可选整理完成，得到最终文本。
3. Sotto 使用听写开始时捕获的语音服务标识创建历史记录并尝试原子保存。
4. 无论历史落盘是否成功，继续现有的浮层关闭流程。
5. 将最终文本放入剪贴板并向当前系统键盘焦点发送 `⌘V`。
6. 历史页面通过可观察 store 自动刷新。

取消、空语音、识别失败或没有得到最终文本时不创建历史。

## 用户界面

### 设置窗口

在左侧边栏“开始”下面新增“历史”，使用 `clock.arrow.circlepath` 图标。

历史页面：

- 顶部标题“历史”和搜索框。
- 说明文字：“仅保存在本机，30 天后自动删除。”
- 记录按时间倒序排列。
- 每条卡片显示本地化时间、语音服务名称和最终文本。
- 文本允许选择，但主要操作是“复制”按钮。
- 每条记录提供删除按钮。
- 页面提供“清空全部”，点击后弹出确认对话框。
- 搜索匹配文本内容，不区分大小写。
- 空状态分别说明“还没有听写记录”和“没有匹配结果”。
- 保存／读取错误以页面内横幅显示，不弹系统模态窗口。

### 菜单栏

- 保留现有“Copy Last Result”作为快速操作。
- 新增“Open History…”，打开现有窗口并直接选择“历史”页面。

### 隐私页

把“转写历史：不保存”更新为“本机保存 30 天”，并明确不保存原始音频。

## 组件边界

### `DictationHistoryEntry`

纯值类型，负责 Codable、Identifiable 和 Sendable。

### `DictationHistoryStore`

主 actor 上的可观察对象，负责：

- 加载和解码
- 30 天清理
- 下一条到期记录的清理任务调度
- 新增
- 单条删除
- 清空全部
- 原子保存
- 对外暴露错误状态

构造时允许注入文件 URL 和时钟，便于单元测试。

### `AppModel`

持有唯一的 history store。在得到最终文本后、调用 `TextInsertionService` 前新增记录。提供打开历史页面和复制历史文本所需的协调入口。

### `SettingsWindowController` / `SettingsRootView`

支持指定打开的设置页面。历史 UI 只调用 store 的公开操作，不自行读写文件。

## 隐私与安全

- 历史为本机明文文件，继承用户账户与 Application Support 目录权限。
- 不同步到云端，不使用 iCloud，不进入 Keychain。
- 文件标记为不参与备份，避免听写内容进入系统备份。
- 诊断日志只记录记录数量、错误类别和文件操作结果，不记录文本内容。
- 删除和 30 天清理后立即持久化。
- README 和隐私页中“当前不保存转写历史”的旧说明必须同步改为“最终文本在本机保存 30 天”；仍明确不保存录音和实时识别片段。

## 测试

核心测试至少覆盖：

- 编解码往返
- 新增后按时间倒序
- 恰好 30 天边界
- 过期记录清理并持久化
- App 长期运行时按下一条到期时间自动清理
- 删除单条和清空全部
- 搜索大小写不敏感
- 损坏文件被保留为备份
- 新增保存失败保留内存记录且不阻止后续粘贴
- 删除／清空保存失败回滚内存变化
- 空／取消／识别失败不写历史
- 有效最终文本在系统粘贴前写入 history store
- 打开历史命令选择正确页面

## 非目标

- 录音保存或播放
- 云同步
- 收藏、标签、编辑、导出
- 重新主动粘贴
- 记录粘贴是否成功或是否复制过
- 保存目标应用或窗口信息
- 无限期保留设置
