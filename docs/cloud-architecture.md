# Ziki Cloud：技术方案

状态：初稿。产品规则见 [产品文档](cloud-product.md)，阶段见 [执行计划](cloud-mvp-plan.md)。

## 模块与技术决策

- `website/`：保留静态 TanStack 预渲染和 SEO；账号页面调用独立业务 API，官网不依赖模型或 Stripe 可用性。
- `cloud/`（待创建）：Workers API、D1 迁移、测试和独立部署；local/staging/production 的数据库、凭证、支付模式隔离。
- 客户端继续 Swift/AppKit/SwiftUI；不迁移 Electron，不为加账号重写录音、热键、静音和插入。
- 最小基础为 Workers + D1；并发/长连接实测需要时才增加 Durable Objects，不预建音频仓库、向量库和微服务群。
- 认证采用维护中的实现，P1 核验 Workers 与原生浏览器登录支持后定案，不手写密码或 OAuth 协议。
- 所有具体 SDK/运行时配置在实现时核验官方文档和生成类型；此文不是已验证的代码样例。

## 客户端改造

复用 `ASRSession`，增加 Cloud 实现；把 `TranscriptPolisher` 抽成可替换接口并保留百炼直连。
服务模式由配置工厂决定；`AppModel` 不判断 Stripe 发票，客户端展示的会员状态不是授权依据。
旧用户默认 BYOK；旧 Keychain、Bundle ID、历史路径不变。Cloud 会话用独立 Keychain 项，可撤销。
保留有界上下文与失败/空结果/不完整结果的原文回退，不重新引入机械词语审核。

## 身份与接口契约草案

原生登录通过系统浏览器；按所选协议采用防截获、防重放机制（例如 PKCE），校验回调，不能凭自定义 URL 中的用户 ID 登录。
Web 请求有 CSRF/Origin/Cookie 防护；原生令牌不放在易记录的 URL 中。身份和试用不依赖可伪造的设备 ID。

P1 固定版本化接口：

- 账号/权益/用量：只返回当前身份数据。
- 创建听写：幂等键 → 会话 ID、短期访问凭证、允许格式/时长。
- 音频上传/流：绑定身份和会话，服务器验证字节、格式、时长、并发。
- 完成/取消/查询：幂等；客户端提交的时长和余额不可直接作为账单依据。
- 整理：绑定授权会话、有界正文/上下文和调用次数，不是任意模型或 URL 代理。
- Checkout/Portal：服务器根据当前用户和允许的产品代号创建。
- Stripe 回调：校验原始请求签名、模式、事件归属和重复处理。

## 数据与一致性

逻辑实体：用户、设备会话、订阅投影、额度授予、听写会话、预留、用量流水、供应商尝试、支付事件。
认证表由认证组件管理，不另造冲突的令牌生命周期。

必须证明的不变量：

1. 支付/试用授予只生效一次，同一会话只结算一次。
2. 可用额度 = 有效授予 − 已消费 − 有效预留，不得为负。
3. 余额检查与预留同一原子操作完成，不能先查后无条件扣减。
4. 预留到期回收与延迟完成有条件状态转换，不能重复释放/扣款。
5. 账期、授予来源和有效期独立记录，不用覆盖余额掩盖退款和过期。
6. 用户额度与供应商成本分开；供应商重试有次数和时长预算。

草案状态：created → reserved → processing → completed / failed / cancelled / expired。
迁移、唯一约束、并发 SQL 必须在本地 D1 集成测试验证，内存 mock 不能证明数据库一致性。

## 支付、模型与部署

Stripe Checkout + Billing + Customer Portal；英国商户、USD Price，服务端持有价格映射，测试/live 不混用。
回调去重并协调当前订阅状态，按确认的付款/账期发额度；覆盖重复、乱序、续费失败、取消、退款和重复 Checkout。
海外模型/区域待实测：固定非敏感样本覆盖英文、口音、中英混说、网络延迟和成本。未经授权不上传个人 BYOK Key。
实时 WebSocket 转发的延迟、长连接成本、取消/重连需要验证，不能预先承诺休眠节省或无限时长。

日志仅保留请求/会话 ID、阶段、耗时、错误分类、用量等元数据；排除音频、正文、上下文、Authorization 和未清洗的上游错误。
缺少配置时拒绝服务；mock 仅测试，不启用公共伪账号或伪成功。staging、官网和正式收费开关独立。
许可和公私有边界确认前，不默认把未来商业后端推入公开仓库。正式计费与生产推广单独确认。

调试、测试频率、发布门槛见 [测试方案](cloud-validation.md)。
